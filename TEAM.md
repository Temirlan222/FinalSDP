# Совместная работа над FinalSDP

Адрес для публикации общего репозитория: [Temirlan222/FinalSDP](https://github.com/Temirlan222/FinalSDP). При создании выбираем приватный доступ; владелец приглашает товарищей позже. Доступ появляется после принятия приглашения.

## Распределение

| Участник | Задачи | Статус этой версии |
| --- | --- | --- |
| Участник 1, Temirlan222 | Strategy, Decorator, расчёт цены, демонстрация и проверки своей части | Реализовано |
| Участник 2 | Factory Method, Builder | Предстоит реализовать |
| Участник 3 | Observer, Facade | Предстоит реализовать |
| Все вместе | Согласовать контракт, собрать общий `Main`, проверить интеграцию и подготовить защиту | После реализации частей |

Текущая версия содержит 2 из 6 паттернов. Документация не засчитывает планы и предложения за готовую работу товарищей.

## Начало работы

После получения доступа:

```powershell
git clone https://github.com/Temirlan222/FinalSDP.git
cd FinalSDP
```

Участник 2 создаёт свою ветку:

```powershell
git switch -c codex/factory-builder
```

Участник 3 создаёт свою ветку:

```powershell
git switch -c codex/observer-facade
```

Перед кодом прочитайте [CONTRACT.md](CONTRACT.md). Обсудите спорные методы с владельцем соответствующей части. Общие интерфейсы в `giftbox.api` нельзя менять в одиночку: такое изменение затрагивает всю команду.

## Передача изменений

1. Работайте в своей ветке и добавляйте только файлы своей части.
2. Проверьте проект: `powershell -ExecutionPolicy Bypass -File .\build.ps1 -Test`.
3. Сохраните изменения коммитом и отправьте свою ветку: `git push -u origin ИМЯ_ВЕТКИ`.
4. Откройте Pull Request в основную ветку репозитория. Кратко укажите, какие паттерны реализованы, как их запустить и какие проверки выполнены.
5. После просмотра изменений другим участником объедините Pull Request и обновите локальную основную ветку через `git pull`.

Если работа другой ветки нужна вашей части, сначала согласуйте порядок объединения. Общий `Main` собирайте после согласования интерфейсов; временный `ExampleGift` из демонстрации не нужно переносить в Factory Method как готовую реализацию.
