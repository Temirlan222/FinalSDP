# Твоя часть: Strategy и Decorator

## С чего начать

Открой проект в IntelliJ IDEA, выбери JDK 11+ и запусти
`src/main/java/giftbox/demo/Demo.java`. Если IDEA не распознаёт исходники,
отметь `src/main/java` как Sources Root. Временный ExampleGift нужен только
для демонстрации без ещё не написанной фабрики товарища.

## Decorator: добавление оформления

1. `Gift` — общий интерфейс подарка. У него есть описание и цена.
2. `GiftDecorator` тоже является Gift, но внутри хранит другой Gift.
3. `GiftWrap` получает цену вложенного подарка и добавляет 200 тенге.
4. `Ribbon` получает цену вложенного подарка и добавляет ещё 100 тенге.

Например, `new Ribbon(new GiftWrap(book))` работает снаружи внутрь:
лента спрашивает цену у упаковки, упаковка спрашивает цену у книги.
Книга возвращает 1500, упаковка возвращает 1700, лента возвращает 1800.
Описание дополняется так же. Исходная книга всё ещё стоит 1500.

`super.getPrice()` означает: сначала получить цену через родительский
GiftDecorator, который обращается к вложенному подарку.
`Math.addExact(a, b)` складывает числа и сообщает об ошибке при переполнении.
Это защитная проверка; сам паттерн — интерфейс Gift и вложенные обёртки.

Фраза для защиты: «Decorator позволяет добавлять оформление во время работы,
сохраняя общий интерфейс Gift. Можно комбинировать упаковку и ленту,
не создавая отдельные классы BookWithWrap, BookWithRibbon и все их сочетания».

## Strategy: заменяемый способ расчёта скидки

1. `DiscountStrategy` — общий интерфейс алгоритма.
2. `NoDiscount`, `StudentDiscount`, `HolidayDiscount` — конкретные алгоритмы.
3. `PriceCalculator` — контекст: хранит выбранную стратегию и вызывает её.
4. `setDiscountStrategy(...)` заменяет правило, сами подарки не меняются.

Для одного набора стоимостью 2600 тенге:

- NoDiscount возвращает 2600;
- StudentDiscount возвращает 2340;
- HolidayDiscount возвращает 2080.

Расчёт скидки `(long) subtotal * 90 / 100` оставляет 90% исходной суммы.
`long` используется во время умножения, чтобы избежать переполнения int.
Целочисленное деление округляет итог вниз: от 999 получится 899.
Сначала считаем всю сумму с оформлением, потом одну скидку на весь бокс.

Фраза для защиты: «Strategy выносит способы расчёта скидки в отдельные
классы с общим интерфейсом. Калькулятор работает через интерфейс,
поэтому правило скидки можно заменить без изменения его расчёта суммы».

## Как соединить с работой остальных

Товарищ с Factory Method создаёт собственные Book, Candle или другие продукты,
реализующие `giftbox.api.Gift`. Твои обёртки уже принимают любой такой объект.
Знание конкретного класса книги им не требуется.

Товарищ с Builder собирает список подарков. Он может добавлять туда уже
оформленные Gift. Builder отвечает за целый бокс, Decorator — за один подарок.

Товарищ с Facade получает список из готового бокса и передаёт его в
`PriceCalculator.calculateTotal(...)`, затем продолжает оформление заказа.
Observer уведомляет о событиях заказа в своей части: твоему коду не нужно
знать, какие именно подписчики получат уведомление.

Перед параллельной работой вместе прочитайте CONTRACT.md и примите имена
пакетов, сигнатуры, единицы цены и округление. Если интерфейс понадобится
менять, меняйте его согласованно вместе со всеми зависимыми частями.

## Что показать на защите

1. Открыть Gift, GiftDecorator, GiftWrap и Ribbon; показать вложенный Gift.
2. Запустить Demo: книга 1500 превращается в подарок с оформлением за 1800.
3. Открыть DiscountStrategy и три стратегии.
4. Показать поле discountStrategy и вызов applyDiscount в PriceCalculator.
5. В Demo показать замену стратегий для одного списка: 2600 -> 2340 -> 2080.
6. Запустить `build.ps1 -Test`: проверки включают чужую реализацию Gift,
   вложенные обёртки, округление и замену стратегии.

Эта демонстрация покрывает только твои два паттерна. Для общей защиты
потребуются четыре реализации товарищей и один общий работающий сценарий.
